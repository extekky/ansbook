#### Что проверяет это задание?

Согласно **официальному кодификатору ФИПИ** (звучит как название секретной организации, но нет), задание проверяет:

> _Формальное исполнение простого алгоритма, записанного на естественном языке, или умение создавать линейный алгоритм для формального исполнителя с ограниченным набором команд, или умение восстанавливать исходные данные линейного алгоритма по результатам его работы._

Если по-человечески: **Вася должен уметь механически выполнять алгоритм, как робот.** Никакой магии, никакого творчества — просто берёшь и делаешь шаг за шагом. Как IKEA, только с числами.

Чаще всего такие алгоритмы — это **перевод чисел в другие системы счисления**. Звучит страшно, на деле — таблица умножения для олдов.

---

#### Рассмотрим перевод числа $123$ в двоичную систему

Вася хочет перевести $123$ из десятичной в двоичную ($СС_2$). Вася берёт Python и пишет простейшую функцию. **Вася доволен. Пока.**

```python
def perevod(n):
    r = ''  # результат (пока пустой, как знания Васи о СС)
    while n > 0:
        r = str(n % 2) + r
        n = n // 2
    return r
```

Это — **программная реализация ручного алгоритма**. Суть проста: делим число на основание новой системы счисления, записываем остатки, читаем их **снизу вверх**. Как читать мангу, только с математикой.

---

##### Пошаговый разбор: $123_{10} \to СС_2$

| Шаг | Делимое | Частное | Остаток | Цифра (справа → влево) |
| :-: | :-----: | :-----: | :-----: | :--------------------: |
|  1  |   123   |   61    |  **1**  |          1-я           |
|  2  |   61    |   30    |  **1**  |          2-я           |
|  3  |   30    |   15    |  **0**  |          3-я           |
|  4  |   15    |    7    |  **1**  |          4-я           |
|  5  |    7    |    3    |  **1**  |          5-я           |
|  6  |    3    |    1    |  **1**  |          6-я           |
|  7  |    1    |  **0**  |  **1**  |          7-я           |

Как только частное стало $0$ — Вася кладёт ручку и идёт пить чай. Процесс завершён.

Собираем остатки **снизу вверх** (читаем таблицу снизу):

$$123_{10} = \underbrace{1\ 1\ 1\ 1\ 0\ 1\ 1}_{2} = 1111011_2$$

Вася счастлив. Вася пишет функцию `perevod`. Вася думает, что всё готово.

**Вася ошибается.**

---

#### Ограничения: Вася встречает основание больше 10

Всё шло хорошо, пока Васе не попалась задача с **шестнадцатеричной системой счисления** (основание 16). И тут у `perevod` начинается экзистенциальный кризис.

Проблема в том, что когда остаток от деления равен, например, $10$ — это уже **не однозначная цифра**. В шестнадцатеричной системе такие значения обозначаются **буквами**:

| Десятичное | Шестнадцатеричное |
| :--------: | :---------------: |
|     10     |         A         |
|     11     |         B         |
|     12     |         C         |
|     13     |         D         |
|     14     |         E         |
|     15     |         F         |

Старая функция Васи пытается написать `str(10)` — и получает `"10"` вместо `"A"`. **Вася сломал число.** Поздравляем.

Чтобы исправить это, Васе нужно добавить **таблицу символов**:

```python
DIGITS = '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ'

def perevod(n, base):
    r = ''
    while n > 0:
        r = DIGITS[n % base] + r  # берём нужный символ из таблицы
        n = n // base
    return r
```

Теперь вместо безликого `str(остаток)` Вася берёт символ из строки `DIGITS` по индексу. $10$ → `DIGITS[10]` → `'A'`. Магия? Нет, просто индексация.

**Вася снова доволен. Вася снова думает, что всё готово.**

---

#### Вася смотрит в бездну: основание больше 36

Строка `DIGITS` заканчивается на букве `Z`, то есть содержит ровно **36 символов** (цифры 0–9 и буквы A–Z). Что будет, если основание системы счисления равно, скажем, $50$?

**Вася попытается взять `DIGITS[36]` — и Python кинет ему `IndexError` прямо в лицо.**

Строка закончилась. Однобуквенных символов на все цифры не хватает. Что делать?

Вася думает... и понимает: **зачем вообще хранить цифры как символы?** Можно хранить их как **обычные числа** в списке! Каждый элемент списка — числовое значение цифры. Никаких букв, никаких ограничений, никакого `IndexError`.

Именно так работает наша следующая функция. Знакомьтесь — **Биба**.

---

#### Биба: переводим число из $СС_{10}$ в любую СС

**Биба** — функция, которая принимает число в виде списка цифр (в десятичной системе) и переводит его в любое основание. Возвращает тоже список — никаких строк, никаких ограничений:

```python
def biba(n_list, base):
    # Сначала собираем число из списка цифр обратно в нормальный int
    n = 0
    for digit in n_list:
        n = n * 10 + digit  # стандартная схема Горнера

    if n == 0:
        return [0]  # ноль есть ноль в любой системе

    r = []
    while n > 0:
        r = [n % base] + r  # остаток — в начало списка
        n //= base
    return r
```

Биба получает на вход `[1, 2, 3]` (то есть число $123$), а внутри сначала склеивает это в $123$, а потом честно делит на основание, собирая остатки в список. Без строк. Без букв. Без нервов.

Пример: `biba([1, 2, 3], 2)` вернёт `[1, 1, 1, 1, 0, 1, 1]` — то самое $1111011_2$.

Вася смотрит на Бибу с уважением. **Но Вася понимает, что Биба умеет только в одну сторону.**

---

#### Боба: переводим обратно в $СС_{10}$

Раз есть Биба — должен быть и **Боба**. Это функция, которая делает ровно обратное: берёт список цифр в произвольной системе счисления и возвращает обычное десятичное число.

```python
def boba(n, base):
    r = 0
    for i in range(len(n)):
        r += n[::-1][i] * base ** i  # позиционная запись числа
    return r
```

Как это работает? Позиционная система счисления — это когда **каждая цифра умножается на основание в степени своей позиции**. Например:

$$1111011_2 = 1 \cdot 2^6 + 1 \cdot 2^5 + 1 \cdot 2^4 + 1 \cdot 2^3 + 0 \cdot 2^2 + 1 \cdot 2^1 + 1 \cdot 2^0 = 123$$

Боба разворачивает список (`n[::-1]`), чтобы удобно считать с младшего разряда, и накапливает сумму. На выходе — честное десятичное число.

Вася запускает `boba([1,1,1,1,0,1,1], 2)` и получает `123`. **Круговорот чисел в природе замкнулся.**

---

#### Биба и Боба вместе: зачем нам оба?

Представим, что Васе нужно перевести число из **шестнадцатеричной** системы в **восьмеричную**. Прямого алгоритма нет. Но есть хитрый план:

1. **Боба** переводит шестнадцатеричное число в десятичное.
2. **Биба** переводит десятичное число в восьмеричное.

Вася использует десятичную систему как **пересадочную станцию**. Как пересадка в Москве, только полезная.

```python
hex_number = [1, 0, 0]       # 0x100 = 256 в десятичной
dec = toDec(hex_number, 16)  # Боба: 256
oct_number = toBase([dec], 8) # Биба: [4, 0, 0]
```

`[4, 0, 0]` — это $400_8$, то есть всё те же $256_{10}$. Вася доволен. **На этот раз по-настоящему.**

---

#### Ключевые идеи для ЕГЭ (и для жизни Васи)

1. **Линейный алгоритм** — никаких ветвлений, просто шаг за шагом. Как конвейер. Как понедельник.
2. **Перевод числа** — делим с остатком, остатки читаем **снизу вверх**. Не перепутать — иначе Вася получит зеркальное число и потеряет баллы.
3. **Восстановление данных** — обратная задача: знаем результат алгоритма, ищем входные данные. Детектив, только с делением.
4. **Основание > 10** — нужна таблица символов. Основание > 36 — нужен список чисел. Не берётся из воздуха: каждое ограничение рождает новое решение.
5. **Биба и Боба** — универсальный дуэт. Биба переводит в любую СС, Боба — обратно. Вместе они непобедимы (в рамках задания ЕГЭ).
