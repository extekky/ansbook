#### №63030 на Решу ЕГЭ

Вася открывает задачник. Вася видит основание $40$. Вася закрывает задачник.

...Вася открывает задачник снова, потому что ЕГЭ не ждёт.

---

#### Условие

В числе $57x692y19_{40}$ $x$ и $y$ обозначают некоторые цифры из алфавита системы счисления с основанием $40$. Определите такие значения $x$ и $y$, при которых приведённое число кратно $39$, а число $yx$ в $40$-ричной системе счисления является полным квадратом. В ответе запишите значение числа $yx$ в $40$-ричной системе счисления в десятичной системе счисления.

---

#### Первая реакция Васи

Вася смотрит на задачу. Задача смотрит на Васю. Основание $40$. Девять цифр. Две неизвестных. Два условия.

Вася понимает, что решать это аналитически — значит добровольно причинять себе вред. Вася вспоминает про **брутфорс**: просто перебрать все возможные значения $x$ и $y$ и проверить оба условия. В $40$-ричной системе каждая цифра принимает значения от $0$ до $39$, значит всего пар — $40 \times 40 = 1600$. Компьютер справится за миллисекунды. **Вася выдыхает.**

Но чтобы проверять условия — числа нужно переводить в десятичную. И тут Вася вспоминает старого друга.

---

#### Боба возвращается

Знакомьтесь — **Боба**. Мы уже встречались. Боба переводит число из любой системы счисления в десятичную, получая на вход список цифр и основание:

```python
def boba(n, base):
    r = 0
    for i in range(len(n)):
        r += n[::-1][i] * base ** i
    return r
```

Напомним как она работает. `n[::-1]` — разворачивает список, чтобы начинать с самой правой цифры (младший разряд). Дальше — классическая позиционная запись: каждая цифра умножается на основание в степени своей позиции, всё суммируется.

**Пример:** число $19_{40}$ — это список `[1, 9]`. Боба разворачивает: `[9, 1]`. Считает:

$$9 \cdot 40^0 + 1 \cdot 40^1 = 9 + 40 = 49_{10}$$

Боба вернула $49$. Боба молодец.

---

#### Основной цикл: Вася перебирает всё

```python
for x in range(0, 40):
    for y in range(0, 40):
```

Два вложенных цикла — перебираем все пары $(x, y)$, где оба значения от $0$ до $39$. Именно такой диапазон, потому что в $40$-ричной системе ровно $40$ цифр: от $0$ до $39$.

Внутри цикла Боба переводит оба числа в десятичную:

```python
        decN = boba([5, 7, x, 6, 9, 2, y, 1, 9], 40)
        decM = boba([y, x], 40)
```

- **`decN`** — десятичное значение числа $57x692y19_{40}$ (то самое девятизначное чудовище)
- **`decM`** — десятичное значение числа $yx_{40}$ (то, что надо найти)

Заметьте: цифры передаются **списком**. Именно поэтому Боба и принимает список — можно напрямую вставить переменные `x` и `y` в нужные позиции. Никакой магии, просто удобно.

---

#### Проверка условий

```python
        if decN % 39 == 0 and (decM ** 0.5) % 1 <= 0 and decM > 0:
            print(decM)
```

Три условия, и все три должны выполниться одновременно:

**Условие 1:** `decN % 39 == 0`

Число `decN` должно делиться на $39$ без остатка. Базовая проверка на кратность — остаток от деления равен $0$.

**Условие 2:** `(decM ** 0.5) % 1 <= 0 and decM > 0`

Число `decM` должно быть полным квадратом. Логика такая:

- `decM ** 0.5` — берём квадратный корень
- `% 1` — выделяем дробную часть (у целых чисел она $0$)
- Если корень целый — число полный квадрат

Почему `<= 0` а не `== 0`? Потому что числа с плавающей точкой — это боль. `math.sqrt(49)` может вернуть `6.999999999` вместо `7.0`, и тогда `% 1` даст что-то вроде `0.999...`, а не $0$. Условие `<= 0` ловит только точные нули, но на практике корни у полных квадратов в Python считаются достаточно точно. Вася проверил — работает.

`decM > 0` — исключаем ноль, потому что $0$ формально является полным квадратом ($0 = 0^2$), но в задаче это явно не тот ответ.

#### Итоговый код целиком

```python
def boba(n, base):
    r = 0
    for i in range(len(n)):
        r += n[::-1][i] * base ** i
    return r

for x in range(0, 40):
    for y in range(0, 40):
        decN = boba([5, 7, x, 6, 9, 2, y, 1, 9], 40)
        decM = boba([y, x], 40)

        if decN % 39 == 0 and (decM ** 0.5) % 1 <= 0 and decM > 0:
            print(decM)
```

Вася запускает код. Код думает примерно ноль секунд. Код выдаёт ответ.

**Вася записывает ответ. Вася идёт пить чай.**

#### Послесловие: почему брутфорс здесь уместен

Это классический **брутфорс** — перебор всех вариантов без аналитических ухищрений. Звучит грубо, работает отлично.

Почему это оправдано:

- Всего $40 \times 40 = 1600$ пар — ничтожно мало для компьютера
- Каждая итерация — несколько арифметических операций
- Весь перебор занимает меньше времени, чем Вася успевает моргнуть

Когда брутфорс **не** оправдан — когда вариантов миллиарды. Но здесь основание $40$, а не $40^{40}$. Вася в безопасности.
